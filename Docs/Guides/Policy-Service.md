# Python request-policy prototype

[`demo/service.py`](../../demo/service.py) and its memory/SQLite engines are **not** the C token-bucket API. They evaluate caller-supplied signals and a peer supplied by the host; they do not authenticate an account or prove a device. See the [engine contract](../Plan/Engine-Contract.md) for charging, retries, duplicate snapshots and intentional backend differences.

The memory engine is process-local and restarts clear its state. SQLite can preserve single-host state for cooperating processes but does not protect against rollback, deletion, data tampering or multiple hosts. Both can deny legitimate users on shared networks or under capacity pressure; forged signals can poison another user's bucket. Operators need independent authentication, authorization and recovery procedures.

The [single-process WSGI integration](../../integrations/wsgi/README.md) enforces host authorization and gate decisions before a protected application with finite local admission. Its [synthetic example](../../examples/python/packaged_wsgi.py) uses the prototype gate. It is not an HTTP server or a reviewed production deployment; network controls, a trusted principal and trusted proxy remain host responsibilities. The older [synthetic WSGI example](../../examples/python/gated_wsgi.py) illustrates host-owned hooks separately. See [deployment status](Deployment.md) for constraints.

An experimental, host-wired [sealed transport key grace mechanism](../Research/Transport-Key-Grace.md) tests overlapping v3 decryption keys without changing pseudonym keys or database state. It is not production key management and does not make backup restore safe; the existing command-line and browser clients remain v2-only.

The prototype policy optionally sets `ip_max_requests` and `device_max_requests` independently, both within one shared `window_seconds`; absent overrides use `max_requests`. Raising the IP threshold reduces some shared-network denial but can allow more abuse; self-reported device signals are forgeable and are not authentication. Changing persistent quota settings changes the SQLite policy fingerprint and existing databases are refused rather than silently reset. An opt-in soft IP challenge and an explicitly privileged shared-IP reset are experimental; see [Shared-IP Recovery](Shared-IP-Recovery.md) for security and abuse caveats.

## Optional local metrics

Pass one `ServiceMetrics()` as `metrics=` to both `Engine`/`SQLiteEngine` and `RequestService` to collect fixed-schema process-local decisions, gate durations, replay/adapter event categories, and memory-lock or SQLite `BEGIN IMMEDIATE` acquisition wait buckets. Capacity and storage failures are counted as decisions, not occupancy gauges; a service call may take multiple serialization samples. Unknown event labels are dropped, and metrics failures must not alter decisions. `python3 tools/synthetic_metrics_dashboard.py` demonstrates synthetic snapshots and illustrative alerts, not tuned production thresholds. Counts reset on restart and do not aggregate processes; no HTTP exporter, authentication, durable monitoring or production dashboard is provided. Parse failures before the service, external queues, replay-store lock wait, and operations outside this prototype are not covered.
