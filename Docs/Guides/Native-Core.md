# Native C core (Linux prototype)

The C ABI in [`include/archx.h`](../../include/archx.h) is currently implemented for Linux. The C core reads Linux installation/firmware signals, constructs an app-scoped HMAC pseudonym and manages a mutex-protected **in-process** token-bucket store. Experimental [Python and Node bindings](../../bindings/README.md) call that ABI and require a trusted explicit library path. It is separate from the Python request-policy engine; their quotas, APIs and persistence are not interchangeable. Experimental Windows/macOS primitive and fixture runs are not full native core or collector support.

For build, installation, API and profile examples see the [root README](../../README.md#build-and-try). `ax_collect` reports metadata, not raw IDs; `ax_identify` returns a pseudonym. ABI-v1 `confidence` is an availability heuristic, not an accuracy probability, and fallback's value 10 is a historical marker. Signals are forgeable and profile matching is not authentication. Keep peppers secret, protect stored profiles, and use `ax_buffer_free` for returned buffers.

New bucket keys fail closed when the store fills; no live bucket is silently evicted. Explicit reset affects a bucket and process/handle destruction resets all quotas. The store is neither durable nor distributed. See [threat model](../Threat-Model.md) and [next-version backlog](../Plan/Next-Version.md) before considering any deployment.
