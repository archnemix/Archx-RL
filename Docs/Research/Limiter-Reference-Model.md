# Synthetic limiter reference-model traces

`tests/test_limiter_model.py` provides partial evidence toward #41, not a release or distributed-enforcement claim. It compares both the process-local memory engine and one-host SQLite engine against a small independent reference using semantic `(signal name, synthetic value)` tuples rather than the production HMAC, SQL or observation-index implementations. Twelve deterministic seeds each run 250 mixed operations with simulated time advances, IP and device quotas, shared IPs, IPv4-mapped addresses, missing and invalid signals, optional second signals, soft challenges, saturation, explicit IP resets, precharged calls, and SQLite restarts. It checks decision, retry interval and matching outcome where applicable. Explicit boundary tests also cover exact window expiry, non-partial charging on capacity refusal, rounding and the longest retry when bucket start times differ.

The reference assumes distinct tuples do not collide, clocks do not move backward, policy does not change, input is syntactically valid except for an explicitly rejected case, and at most 24 entries remain live (below the 64-item cleanup budget). Simulated precharged calls exercise the engine flag, not an end-to-end authenticated precharge workflow. These tests do not exercise concurrent interleavings, host integration, physical devices, secret management, crashes, distributed partitions, backend fault injection, production scale or arbitrary input sequences. Seeded traces and examples are not an exhaustive proof; other model, fuzz, fault, coverage, browser, staging and soak requirements of #41 remain open.
