# Empty SQLite schema-2/3 transition experiment

This is a narrow experiment toward #13, **not a supported migration of active state or a backup/restore protocol**. `demo/empty_schema_migration.py::migrate_empty_schema` changes metadata atomically between the historical schema 2 immediately preceding commit `7ad21f1` and current schema 3, in either direction, only if all quota windows, observations and signal rows are entirely empty. Even expired rows cause refusal. It accepts only unchanged canonical policies expressible in the historical version, the same secret, the exact historical/current table and index definitions, and exactly the three expected metadata entries. Any replay schema, marker or other unknown object or metadata is rejected even when empty. It checks SQLite integrity and foreign keys, a private owned regular database file and private owned directory, and serializes the check and metadata updates in an immediate writer transaction. It does not delete or transform rows.

The operator must **stop and drain every writer, including older binaries**, throughout migration and until the intended version is running. Older code does not perform transaction-time metadata checks; merely obtaining the SQLite lock during this operation does not prevent an already-running older process from writing afterwards. Control the directory and all path ancestors and do not allow an untrusted user or the service UID to race file replacement. Restore, stale snapshots, revocation, time correctness, power-loss durability, key custody, replay migration and historical versions other than the specified schema remain unsolved. An error after a commit attempt can be ambiguous: stop all writers and inspect state before retrying. This function provides no CLI or production deployment recommendation.

For an explicitly controlled experiment, a caller supplies `path`, secret, canonical unchanged policy and `source=2, target=3`; the reverse direction specifies `source=3, target=2`. `SQLiteEngine` refuses schema 2 and must only be constructed after a successful upgrade. Downgrade is refused after any quota/history state appears, and after replay is initialized, rather than silently discarding it. This empty-only operation cannot recover or re-key active schema-2 pseudonyms; original input values are unavailable. Never copy a live database's main file as a backup or treat an old database as a safe rollback.

`tests/test_empty_schema_migration.py` uses synthetic data and both an exact historical schema/metadata fixture and frozen historical engine/SQLite code from commit `2756e40ce32f28cc4a5e6cc8d691c3c1cd4eea44` in an isolated subprocess. It checks historical initialization, upgrade and current-engine restart, refusal by a freshly started old engine, empty rollback and historical restart. It also tests rejection of rollback with quota state, expired-row refusal, orphan/replay/unknown-object checks, private-file checks, injected failure on the second metadata update, and a waiting migration observing a committed SQLite writer. Tests do not execute the complete historical service or demonstrate real crash, concurrent old-writer, tampering, or physical storage guarantees. #13 remains open until active-state migrations and supported backup/restore and rollback are resolved.
