# Internal profile-scope adapter

This is partial portability work toward #6 and #30, **not Windows or macOS product support**. The internal collector interface provides a fixed process-lifetime enum rather than allowing the common core to assume `linux` when generating capability metadata or deriving and validating ABI-v1 profile scope. The core maps only recognized enum constants to fixed ASCII strings; an unrecognized scope fails closed instead of emitting or accepting a profile. Production Linux selects the original `linux` value, retaining the existing Linux scope digest and metadata. The other currently defined value is `synthetic`, reserved for isolated fixtures, not an advertised platform.

`tests/platform/test_core_synthetic.c` checks a known Linux scope digest, a distinct synthetic scope digest, rejection of an incompatible Linux profile under the synthetic scope, an internally invalid scope, and synthetic capability metadata. The fixture changes the scope solely to exercise the boundary; real adapters must not change scope during a process lifetime. Native Windows/macOS CI runs the common core only with this synthetic collector. Profile scope is a domain separator, **not** a signature, authentication or tamper protection; profiles still need trusted storage. This interface does not implement non-Linux collection, native persistent fallback, release packaging, or an approval to collect hardware data. Further OS-specific scope and signal semantics require explicit design and compatibility testing.
