# Synthetic C input fuzz smoke

The C JSON parser, public configuration and profile-comparison paths have a small coverage-guided smoke harness in `tests/fuzz_core_inputs.c`. It supplies arbitrary bytes and lengths to the JSON parser and `ax_core_new`, then compares a valid synthetic IP-only profile with the input through `ax_compare`. Results and allocated buffers are checked and freed; a synthetic collector prevents OS identifier reads. The test does not exercise live hardware, HTTP, persistence, bindings or the whole public API.

`sh tests/fuzz_core.sh` requires clang/libFuzzer, ASan and UBSan. It compiles the current core with a synthetic collector, creates four small test-only corpus seeds, removes inherited environment variables before executing, runs for five seconds with a maximum input length of 8,192 bytes, and removes its temporary corpus/artifacts on exit. Linux PR/push CI runs it in addition to the separate SMBIOS fuzz smoke. A nonzero fuzzer exit fails CI; treat generated artifacts as untrusted and inspect crashes privately if they contain sensitive input. No real credentials or host signals are used. A deterministic `tests/fuzz_core_driver.c` also calls the same harness on synthetic fixtures, 500 seeded binary inputs and size boundaries in the normal and ASan/UBSan local regression, without requiring libFuzzer.

This is a short smoke, not evidence of comprehensive coverage, crash absence, independent security review or a vulnerability-free parser. It does not provide the scheduled longer fuzzing, full fuzz target set, coverage reports, credentialed staging or agreed production soak targets required for release gate #41, which remains open.
