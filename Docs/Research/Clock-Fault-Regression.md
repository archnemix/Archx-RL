# Synthetic local clock-fault regression

This is targeted work toward #41, not a complete test matrix or a production security guarantee. The Python demo's in-memory and SQLite quota/history paths and replay stores depend on an injected wall-clock function. Before this regression, a synthetic NaN or infinite clock sample could reach pruning and delete pending replay entries or quota/history state; some other malformed samples caused unhandled exceptions. This is an injected fault, not evidence of a remotely reachable clock-control vulnerability.

The engine now rejects invalid types, booleans, non-finite or unrepresentable values, clock exceptions and timestamps outside its supported Python datetime conversion range before modifying quota/history state. It reports storage unavailability on request paths; maintenance raises a sanitized error. The two engines sample under their lock/SQLite writer transaction, so a fault after pre-transaction preparation fails closed rather than clearing state. The replay stores likewise validate the sample and representable expiry before pruning, issuing or consuming, and report `ReplayUnavailable` on request paths. Both SQLite transactions roll back on faults. Existing configuration accepts finite replay TTLs of 1–300 seconds and integer capacities; invalid types now fail startup.

`tests/test_engine_clock_faults.py` and `tests/test_replay_clock_faults.py` exercise malformed and non-finite clocks, huge numbers, clock exceptions, preserved state, recovery, and unavailability at the service boundary. They compare in-memory and SQLite paths; engine tests also inject a failure after request preparation. `test.sh` runs both. They do not simulate arbitrary clock changes in another process, filesystem rollback or power loss.

This validation **does not detect a plausible but incorrect finite time**, including forward jumps that expire state early or backward jumps that extend it. It does not establish trusted time, monotonicity, cross-process synchronization, durable replay fencing or safe backup/restore. A host must treat time and persistent state as operational/security dependencies; #13 and #41 remain open.
