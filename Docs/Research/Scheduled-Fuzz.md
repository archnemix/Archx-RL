# Extended synthetic fuzz workflow

`Synthetic extended fuzz` defines a weekly scheduled run plus manual dispatch on the GitHub default branch. A push that changes the workflow on the current working branch also exercises it once; that push run is **not** evidence that the schedule has executed. GitHub schedules do not start from a non-default branch, may be delayed or disabled by GitHub, and require monitoring after integration. No scheduled run has yet been observed.

Each run uses synthetic seeds and unprivileged, read-only repository permissions. It runs 30 seconds each of the existing SMBIOS, C JSON/config/profile and Python normalization/sealed-envelope coverage-guided targets, with temporary corpora/artifacts cleaned after each command. Five-second smoke runs remain in PR/push Linux CI. `ARCHX_FUZZ_SECONDS` permits an integer from 1 through 300 for local experimentation; it defaults to five seconds. libFuzzer may run beyond the nominal interval while completing an input or shutting down. Fuzzing never contacts a provider or reads device identifiers. The workflow uses Python 3.12 for Atheris compatibility and clang sanitizers for C.

A short push-triggered exercise is only evidence for that specific runner, code and time budget. It does not establish scheduled execution, exhaustive coverage, freedom from vulnerabilities, target coverage for every language/format or a retention/triage process for long-running fuzzing. Logs and synthetic failure inputs should be reviewed before publication. The wider #41 release gate, staging and independent review remain open.
