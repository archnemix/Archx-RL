# ADR: C crypto and JSON providers

**Status:** evaluation and interim decision, 2026-11-22; no provider replacement or format migration is performed here. Owner review, project license selection and release packaging remain open. The native C core is an unaudited Linux prototype, not a production cryptographic boundary. This ADR is not legal or security certification.

## Requirements

Preserve the existing SHA-256/HMAC-SHA256 bytes, domain separation, app-scoped pseudonym and profile formats unless a separately versioned migration is explicitly approved. The parser must reject duplicate decoded object keys, unsupported arrays, embedded NUL and surrogate escapes, non-finite numbers, excessive depth/children and trailing garbage under the present contract. Security-sensitive input needs an explicit byte/memory budget, deterministic locale-independent numeric parsing, predictable failures and fuzz/fault coverage. Auditability and maintainable security updates matter more than minimal source size. Neither a cryptographic match nor a signal match authenticates a user or device.

Licenses and source size are not legal compatibility analysis, audit evidence, dependency vulnerability screening, or package-size measurements. Recheck versions, notices, availability, platform distribution and update policy before adoption. No external code is vendored by this ADR.

## Interim decision and migration gate

Keep the existing implementations for the current prototype while evaluating a maintained provider; do **not** silently swap algorithms, relax parser validation or advertise the prototype as audited. Preference for a later production candidate is libsodium's SHA-256/HMAC streaming APIs with an adapter and a separately evaluated bounded JSON wrapper, subject to maintainer, legal, packaging and security review; OpenSSL remains an alternative. If an adapter produces byte-identical outputs and identical accepted inputs, verify compatibility on every supported native target before rollout. A changed hash algorithm, key interpretation, domain separator, JSON grammar or profile schema requires an explicit versioned migration, preserved legacy-read tests, operator rollback/recovery plan and no silent identity/quota resets. The future provider itself must be differential-tested; the present fixtures test only the existing implementation.

## Evidence and remaining work

`tests/test_vectors.c` checks published SHA-256/HMAC vectors. `tests/test_crypto_differential.py` compares 469 deterministic synthetic messages, chunking and key sizes with Python `hashlib`/`hmac`. `tests/test_json_contract.c` exercises selected grammar boundaries, while `tests/test_json_fuzz.c` performs deterministic malformed-input stress on Linux. The native experimental matrix compiles standalone synthetic crypto/JSON fixtures and runs the same Python differential test against a fixture-only shared library; it is not the full product library or an external-provider comparison. Actual per-platform CI results must be linked after execution, not inferred from configuration. Fault injection, an explicit total-allocation budget, locale/UTF-8 handling, dependency build/size, independent review, any provider swap and production packaging remain open.
