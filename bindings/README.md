# Experimental C-core bindings

The Python and Node wrappers in this directory use the **same Linux C ABI v1**, not the separate Python request-policy engine or browser client. They are source packages in this repository, not published releases; version `0.0.0` is an unreleased packaging placeholder, not a support/version promise. The advertised and tested binding target is Linux x86-64; other architectures, Windows and macOS have not been validated for the complete core and bindings. Windows/macOS primitive fixtures do not establish binding or full-core support. No production-readiness, authentication, identity-proof or distributed quota claim is made.

Build the C core with `./build.sh`. Supply an **absolute path to a trusted library** and an explicit configuration. Native library loading executes code in the host process: ABI checks cannot establish provenance or make an untrusted library safe. Python can import via `PYTHONPATH=bindings/python`, or install the local package with `python -m pip install ./bindings/python`. For Node, install the locked dependencies with `npm ci --prefix bindings/node`. See `examples/python/{demo,match}.py` and `examples/node/demo.js`; their fallback demo peppers are public and their output can contain linkable pseudonyms.

Both wrappers check `ax_abi_version` before calling the rest of the interface, expose collection, identification, profiles, comparison, quota checks and reset, and free C-owned JSON buffers even on native or decoding errors. A denied quota is returned as `rate_limited`; native errors raise `ArchxError` instead of being mistaken for a denial or allow. C-string arguments must be well-formed Unicode without embedded NULs. Python accepts costs up to signed 64-bit maximum; Node accepts positive safe integers and may return a BigInt for large native 64-bit results. Python `Core` is a context manager and serializes each operation against `close()`; Node calls are synchronous and an object/handle must not be transferred across worker isolates. Explicitly call `close()`; repeated close is harmless. Do not close a Python core by manipulating its private handle, or mutate its native state outside the wrapper. The C core has process-local state, resets on destruction, and requires independent host authentication and authorization. Caller-supplied IPs must come from a trusted transport boundary; profiles and pseudonyms are linkable and not self-authenticating.

The optional `core.capabilities()` reports [versioned signal capability metadata](../Docs/Guides/Capability-Schema.md) when the loaded ABI-v1 library implements that extension. It reports a clear error with older ABI-v1 libraries and does not fabricate statuses.

The wrappers do not install or select a native library automatically, validate its origin, protect peppers from the host process, free arbitrary buffers allocated outside their calls, or make native code memory-safe. Do not log profiles, secret keys or raw identifiers. Loading malicious/incompatible libraries can crash the process even if they report ABI 1.

`tests/fixtures/native-binding-v1.json` is a single deterministic synthetic IP-only fixture used by both languages; it does not collect or log a host identifier. The Python test independently checks fixture HMACs. Both tests exercise profile matching, unavailable/changed states, quota and reset, native errors, incompatible ABI, and C-buffer release after success, error, malformed JSON and abnormal length using a synthetic C library. Python additionally exercises concurrent close. Run `./test.sh` after installing the Node dependency; the Node test otherwise reports an explicit skip, or set `ARCHX_REQUIRE_BINDINGS=1` to make a missing Node dependency fail. Linux CI requires and runs both; no other platform is advertised by these bindings.
